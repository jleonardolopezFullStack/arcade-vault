### Data flow conventions

- **Reads return `Result<T>`** (`lib/result.ts`): `{ok:true,data}` | `{ok:false,error}`, so "no data" ≠ "couldn't ask". Use `readFailed(where, cause)` — logs the raw error server-side, returns `SIGNAL_LOST` (Spanish) to the screen.
- **Catalog**: `lib/catalog.ts` (`listGames`, `listGamesWithStats`, `getGame`, `listGameIds`, `CATS`). **Leaderboards**: `lib/leaderboard.ts` (`topScores`, `allTopScores`, `scoresFor`). Both read Supabase; there is no mock data left.
- **Writes are Server Actions**, not route handlers. Score: `app/juegos/[id]/jugar/actions.ts` → RPC `submit_score` (validation in `lib/submit-score.ts`). Contact: `app/acerca-de/actions.ts` (Zod schema in `lib/contact.ts`, email template `emails/contact-message.tsx`). Both rate-limited per IP by `lib/rate-limit.ts` (in-memory, separate buckets, not production-grade).
- **Session is still a placeholder**: `lib/session-context.tsx` keeps an arcade alias in `localStorage['av_user']`, read only inside `useEffect` (hydration). No real auth yet — `submit_score` is the first thing to revisit when it arrives.
- Formatting helpers: `lib/format.ts` (`formatScore`, `formatDate`).

### Games

Engines live in `lib/games/<concepto>/` and implement the contract in `lib/games/types.ts` (`GameEngineFactory(canvas, hooks) → { start, pause, resume, restart, destroy }`; hooks `onSnapshot({score, lives, level, lines?})`, `onGameOver(score)`). The player only knows that interface. `lib/games/input.ts` (`isTypingTarget`) keeps keyboard from leaking out of form fields.

## Supabase

Project `ekcduxcscntnisfhbiqc`, reachable through the Supabase MCP (`.mcp.json`). Env vars in `.env.local` (ignored), documented in `.env.template`:

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — the `sb_publishable_...` key, **not** legacy `anon`.
- `RESEND_API_KEY` (absent → **simulation mode**: email logged to console), `CONTACT_TO_EMAIL`, `CONTACT_FROM_EMAIL` (must be a verified domain or `onboarding@resend.dev`).
- `SUPABASE_DB_PASSWORD` is not read by the app.

**Clients** in `lib/supabase/` (config via `supabaseEnv()` in `env.ts`, which names the missing var):

- `read.ts` → `createReadClient()`: cookieless, for public data (`games`, `game_stats`, `top_scores()`). The only one usable in `generateStaticParams()`. Never for session-dependent data.
- `server.ts` (async; Server Components/Actions/route handlers), `client.ts` (browser), `proxy.ts` (`updateSession`).
- **Session refresh lives in root `proxy.ts`, not `middleware.ts`** (renamed in Next 16). In `updateSession` put no code between `createServerClient` and `auth.getClaims()`, and never return a response other than `supabaseResponse` without copying its cookies.

**Schema** (details and accepted advisor warnings in `supabase/README.md`):

- `games` catalog + **one score table per game** (`scores_rocas`, `scores_caida`, …), unified by views `leaderboard` and `game_stats`; functions `top_scores(p_game)` and `submit_score(p_game, p_name, p_score)`.
- RLS grants only `SELECT`. The **only write path** is `submit_score` (`security definer`, `search_path = ''`, validates game, alias ≤10 uppercase, `0..games.max_score`, keeps best per alias).
- **Adding a game to the DB = 3 things**: its `scores_<slug>` table, **its branch in the `leaderboard` view** (forgetting it fails silently: empty ranking forever), and its `games` row. Template at the end of `supabase/migrations/20260926091843_vistas_y_funciones.sql`.

**Migration workflow** — the Supabase CLI is not used (no `config.toml`, no local stack). `supabase/` is a copy of what was applied:

1. Write `migrations/<ts>_<name>.sql` **and** its `rollback/NNN_<name>.down.sql`.
2. Apply with MCP `apply_migration`; rename the file to match `list_migrations`.
3. Regenerate `lib/database.types.ts` with `generate_typescript_types` (never edit it by hand).
4. Run `get_advisors`; only the three documented warnings are acceptable.

## Skills & workflow

Spec-driven: one spec per feature in `specs/NN-slug.md`, then implement on branch `spec-NN-slug` → PR to `main`. Skills live in `.claude/skills/` and are mirrored in `.agents/skills/` (external ones pinned in `skills-lock.json`):

- `/spec` → design a feature spec (writes `specs/`, no code). From `Klerith/fernando-skills`.
- `/spec-game` → same for a **new game**: asks guided questions, reads the real state of `public.games`, bakes in the engine contract (`contrato-motor.md`) and leaderboard migration (`migracion.md`). No code, no DB writes.
- `/spec-impl` → implements an approved spec; creates the branch automatically (`specs/.spec-config.yml`: `AutoCreateBranch: true`).
- `supabase-postgres-best-practices` → load before any schema/migration/RLS/SQL work.
- **Always use `/frontend-design` for UI work.**

## Design prototype

`references/templates/` is a standalone HTML/JSX mockup (React 18 UMD + Babel, no build) — the visual/behavioral reference all screens were ported from. **Port from it, never edit it**, and don't carry its no-bundler conventions (globals on `window`, aliased hooks, hash routing, `localStorage` scores, `seededScores`) into the app.

Its `styles.css` neon-retro theme now lives in `app/globals.css`: tokens `--bg`, `--ink`, `--cyan`, `--magenta`, `--yellow`, `--green`, `--gold/silver/bronze`, `--line`; fonts `Press Start 2P` (`--pixel`) and `JetBrains Mono` (`--mono`); `.av-bg` grid, `.av-noise` scanlines, CRT effects, `.cover-*` classes referenced by `games.cover`. Reuse these tokens — don't invent colors. Shared primitives in `components/ui/` (`button`, `chip`, `panel`, `signal-lost`).
