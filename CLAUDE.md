## Stack

Next.js 16.3.3 (App Router) · React 19.2.8 · TypeScript strict · Tailwind CSS v4 (PostCSS plugin, no `tailwind.config`). Import alias `@/*` → repo root.

Next 16 / Tailwind 4 specifics already visible in the scaffold — follow them instead of older patterns:

- Route component props come from **globally generated types**: `LayoutProps<"/">`, and the equivalents for pages/route handlers. Don't hand-write `{ children }: { children: React.ReactNode }`.
- Theme lives in `app/globals.css` via `@import "tailwindcss"` + `@theme inline`, not a JS config file.
- `AGENTS.md` is machine-generated by `next dev` (see `node_modules/next/dist/server/lib/generate-agent-files.js`); commit it with your changes rather than reverting it.
- Next's own docs ship in `node_modules/next/dist/docs/` — consult them for anything version-sensitive.

## Supabase

Conectado desde SPEC 04. Dos variables, ambas en `.env.local` (ignorado) y documentadas en `.env.template` (versionado):

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — la clave `sb_publishable_...`, **no** la `anon` heredada.

`SUPABASE_DB_PASSWORD` está en el entorno pero la aplicación no la lee: es para el CLI o un cliente SQL.

- **Clientes** en `lib/supabase/`: `client.ts` (componentes cliente), `server.ts` (Server Components, Server Actions y route handlers, `async`) y `proxy.ts` (`updateSession`). La configuración se lee con `supabaseEnv()` de `lib/supabase/env.ts`, que falla nombrando la variable que falte.
- **El refresco de sesión vive en `proxy.ts` de la raíz, no en `middleware.ts`**: Next 16 deprecó esa convención y la renombró. Dentro de `updateSession` no metas código entre `createServerClient` y `auth.getClaims()`, ni devuelvas una respuesta distinta de `supabaseResponse` sin copiarle las cookies.
- **Tipos**: `lib/database.types.ts` está generado (MCP de Supabase, `generate_typescript_types`). No editarlo a mano; regenerarlo tras cada migración que cambie el esquema.
- **Diagnóstico**: `GET /api/supabase/health` → `{"ok":true,"hasSession":false}` si la conexión responde, `503` si falla.

## Design prototype — the spec source

`references/templates/` is a tracked, standalone, runnable HTML/JSX mockup of the whole product. It has **no build step**: `Arcade Vault.html` pulls React 18 UMD + Babel-standalone from unpkg and loads each `.jsx` as `<script type="text/babel">`. Open the HTML directly to see it.

Treat it as the visual and behavioral reference and **port from it** rather than editing it. Its conventions exist only because of the no-bundler setup and must NOT carry into the Next app:

- Every component is a global (`window.Nav = Nav`, `window.GAMES = GAMES`, …); hooks are aliased per file (`useState: useStateP`) to dodge redeclaration across scripts.
- Routing is a JSON route object (`{ name, id }`) round-tripped through `location.hash` in `app.jsx` → becomes real App Router routes.
- Session and scores are `localStorage` (`av_user`, `av_scores`); leaderboards are fabricated by `seededScores(seed, count)` in `data.jsx`; gameplay in `reproductor.jsx` is a `setInterval` faking a rising score. All three are placeholders for real auth, persistence, and actual games.

Screens → routes to build (file names mirror the Spanish screen names):

- `biblioteca.jsx` — `Library` + `GameCard` catalog, category chips, mouse-tilt cards
- `detalle.jsx` — `GameDetail`: cover, long copy, stat strip, per-game score table
- `reproductor.jsx` — `GamePlayer`: CRT frame + HUD (player, score, lives, level), pause/end/exit, game-over score submit
- `auth.jsx` — `Auth`: login/signup tabs, guest play, social buttons (all cosmetic)
- `salon.jsx` — `HallOfFame`: per-game tabs, 3-slot podium, ranked table
- `nav.jsx` — top nav + mobile drawer; `app.jsx` — router/session shell
- `data.jsx` — `GAMES` mock array (`id, title, short, long, cat, cover, color, best, plays`), `CATS`, `PLAYERS`, `seededScores`

`styles.css` (950 lines) is the neon-retro theme and the thing to preserve: CSS custom properties (`--bg`, `--ink`, `--cyan`, `--magenta`, `--yellow`, `--green`, `--gold/silver/bronze`, `--line`), `Press Start 2P` for display (`--pixel`) and `JetBrains Mono` for body (`--mono`), plus the fixed `.av-bg` perspective grid, `.av-noise` scanlines, CRT effects, and per-game `.cover-*` gradient classes referenced by `game.cover`. Porting a screen means bringing its tokens into `@theme inline` in `app/globals.css`, not re-inventing colors.
